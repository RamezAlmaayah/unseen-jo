# Content publishing workflow

This document was absent when the content-completion task began. It documents the existing Phase 04 architecture; it does not grant permissions or change policies.

1. Sign in through the existing Admin Dashboard at **http://127.0.0.1:4184/admin** using your own verified account. Credentials and verification links remain private. The database requires an existing admin role and matching active Auth session.
2. Open the existing destination by UUID. Keep its ID and slug. Save sourced content as **draft**. Preserve unknown fields as NULL. Ordinary draft edits clear previous claims/location verification; review the saved values again after edits.
3. Record location precision honestly. An official area pin or heritage-property reference is not necessarily an entrance. Use the map, manual coordinates, source and Review notes; confirm visitor arrival/access where necessary. Do not mark a location reviewed solely because a coordinate or URL exists.
4. Upload a lawful image through the CMS's private Storage workflow. JPEG/PNG/WebP, maximum 5 MiB. Never overwrite/delete the old upload without separate authority. Set alt text, source URL, author/attribution, rights basis and evidence; preserve licence version, required notices and modification disclosures. Metadata changes reset saved rights approval.
5. Review the **saved** photo and evidence, then choose **Approve saved rights evidence** only when justified. The RPC requires an actual administrator session, matching timestamp, existing object and evidence constraints. An unverified test image remains unapproved; adding another cover does not clear it.
6. For this local research package only, **http://127.0.0.1:4184/admin/content-completion** can upload the inspected files through the same repository operations and verify private retrieval. It never publishes, approves rights or completes claims/location reviews. It refuses unexpected project/IDs/paths and checks file hashes. Keep the page open and inspect errors before retrying; incomplete metadata linking must be reconciled in the normal editor.
7. Preview the actual saved draft and private signed images. Verify text, geographic pin, image identity, alt text, crop/quality, source and credit delivery. Inspect the public credit implementation before using an attribution-required image publicly; current plain-text credit in the opened gallery does not establish discoverable source/licence links across public views.
8. Review final saved claims and location evidence and use **Record review of saved draft**. The existing RPC records the actual account/time. Trusted SQL research preparation never impersonates that account or creates a completed review on its behalf.
9. Refresh the database **Publication checklist**. It requires a useful description, non-demo content, explicit claims review, active assigned primary category, sourced/reviewed Jordan coordinates with precision and an uploaded rights-approved cover. This runs on the database boundary, including direct publication writes. Field/evidence presence cannot prove factual truth or legal rights.
10. For this task, **stop before Publish**. The owner must separately approve publication of the exact destination after seeing its final content, location/access evidence, image rights and clean checklist. Only then use the existing Publish confirmation.
11. Following approved publication, inspect fresh anonymous Home (first three published entries in slug order), Explore, `/map` and `/places/<slug>`, approved images/credits and audit history. Confirm all other drafts and archived places remain hidden. Do not substitute a fixture test for this actual public acceptance.

All six destinations currently remain drafts. This workflow does not authorize role grants, RLS/Storage changes, publication, unrelated-project actions or Phase 05.
